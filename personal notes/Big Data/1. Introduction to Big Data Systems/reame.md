# Big Data Course — Lesson 1: Introduction to Big Data Systems

Topics: What is Big Data, Business Value, Big Data Roles, When to Use/Not Use Big Data, History (Hadoop & Spark).

---

## 1. What is Big Data?

- Not a single technology — an entire **field/concept**, hard to define precisely.
- Provides ways to work with **massive/complex data sets** that traditional data-processing software **can't handle**.

⚠️ MCQ trap: Big Data is best described as a **concept**, not a specific tool or product.

---

## 2. Business Value of Big Data

Big Data provides value in these ways:

- **Improved products & services**
- **Cost reduction & revenue increase**
- **Faster, better decision-making** by executive teams
- Identifying new opportunities → smarter business moves, efficient operations, higher profits, happier customers
- Better control of data → cost reduction, better decisions, innovation

---

## 3. Big Data Roles (classic matching MCQ)

| Role               | Responsibility                                                                                                                               |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **Data Engineer**  | Implements & manages the **backend/infrastructure** of Big Data systems; must be efficient with Big Data tools; delivers results **quickly** |
| **Data Scientist** | **Researches, compares, and analyzes** opportunities related to company data                                                                 |
| **Data Architect** | **Bridge** between business/technical leadership and the engineering team; understands requirements, proposes solutions, provides rationale  |

⚠️ MCQ trap — don't confuse these three:

- **Engineer** = builds/manages the infra (implementation)
- **Scientist** = analyzes/researches data (insights)
- **Architect** = bridges business ↔ engineering (translation/strategy)

📌 According to IBM, Big Data jobs were expected to **grow 40%**.

---

## 4. When to Use Big Data

Use Big Data when:

- Data amounts are **massive and steadily increasing**
- Existing systems **can't scale** anymore / at max capacity
- You have **physical or logical silos** (data or people) that need bridging
- Executive teams want **new data insights**
- **Speed and efficiency** matter to you/your customers

### When NOT to Use

- If data is **small and unchanging** — limited benefit from Big Data approaches (though worth staying open to future needs).

⚠️ MCQ trap: The deciding factors are **scale, growth, silos, need for insight, and speed** — not just "having a lot of data."

## 5. History — Hadoop & Spark

| Year                  | Milestone                                                       |
| --------------------- | --------------------------------------------------------------- |
| **2003**              | Google publishes research paper (**Google File System**)        |
| **2006**              | **Hadoop** — first open-source version, rolled out by **Yahoo** |
| **2013**              | **Apache Spark** released                                       |
| Present (course time) | Both Hadoop and Spark are on **3.0 release**                    |

⚠️ MCQ trap: **Hadoop is based on Google's research paper** (Google File System, 2003) — Google didn't build Hadoop; Yahoo open-sourced it based on Google's concepts.
