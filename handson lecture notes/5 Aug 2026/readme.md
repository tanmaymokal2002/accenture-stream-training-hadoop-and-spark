# Part 2 — `find()` vs `findOne()`, Projections & Pagination

## 2.1 `find()` — return all matching documents

```javascript
db.empFile.find({ Gender: "Female" });
```

- Returns an **array** of every document that matches the filter.

## 2.2 `findOne()` — return a single document

```javascript
db.empFile.findOne();
```

```
{
  _id: ObjectId('6a71af643e805a09e77a2885'),
  emp_id: 1201,
  Name: 'gopal',
  Age: 45,
  Gender: 'Male',
  Salary: 50000,
  Designation: 'AM',
  Dept_id: 'D001'
}
```

- **Why:** with no filter, `findOne()` just returns the first document in the collection's natural order — useful for a quick peek at document shape without pulling back the whole collection.

```javascript
db.empFile.findOne({ Dept_id: "D001" });
```

- With a filter, returns only the **first** matching document — unlike `find()`, which would return every match as an array.

## 2.3 Projections — choosing which fields come back

**Inclusion projection** — only the listed fields are returned (plus `_id` by default, unless explicitly excluded):

```javascript
db.empFile.findOne({ emp_id: 1201 }, { _id: 0, Name: 1, Salary: 1 });
```

```
{ Name: 'gopal', Salary: 50000 }
```

**Exclusion projection** — every field is returned _except_ the ones listed:

```javascript
db.empFile.findOne({ emp_id: 1201 }, { Age: 0, Gender: 0 });
```

```
{
  _id: ObjectId('6a71af643e805a09e77a2885'),
  emp_id: 1201,
  Name: 'gopal',
  Salary: 50000,
  Designation: 'AM',
  Dept_id: 'D001'
}
```

- ⚠️ **You can't mix inclusion and exclusion** in the same projection (aside from `_id`, which is always allowed to be excluded on its own):

```javascript
db.empFile.findOne({ emp_id: 1201 }, { Name: 1, Age: 0 });
```

```
MongoServerError[Location31254]: Cannot do exclusion on field Age in inclusion projection
```

- Once a projection has any field set to `1` (inclusion mode), every other field must also be `1` — you can't then set a different field to `0`, since Mongo can't tell whether the projection as a whole is meant to include-only or exclude-only.

## 2.4 Sorting

```javascript
db.empFile.find().sort({ Age: -1 });
```

- `-1` = descending, `1` = ascending. Sorts every document in the collection by `Age`, oldest first.

## 2.5 Limiting results

```javascript
db.empFile.find().sort({ Age: -1 }).limit(2);
```

```
[
  { _id: ObjectId('6a71af643e805a09e77a2885'), emp_id: 1201, Name: 'gopal', Age: 45, ... },
  { _id: ObjectId('6a71af643e805a09e77a2886'), emp_id: 1202, Name: 'manisha', Age: 40, ... }
]
```

```javascript
db.empFile.find().sort({ Age: 1 }).limit(2);
```

- `.limit(n)` caps the result set to `n` documents, applied **after** the sort — so this reliably gets you the top-N or bottom-N rows.

## 2.6 Pagination — `skip()` + `limit()`

```javascript
db.empFile.find().sort({ Salary: -1 }).skip(1).limit(1);
```

```
[
  { _id: ObjectId('6a71af643e805a09e77a2886'), emp_id: 1202, Name: 'manisha', Salary: 50000, ... }
]
```

```javascript
db.empFile.find().sort({ Salary: -1 }).skip(2).limit(1);
```

- **Why:** `skip(n)` drops the first `n` documents from the sorted result before `limit()` applies — combining the two is the standard way to fetch "page 2," "page 3," etc., or to grab the 2nd-highest / 3rd-highest row without an aggregation pipeline.
- ⚠️ `skip()`/`limit()` only exist on **cursors** (what `find()` returns), not on a single document. `findOne()` doesn't return a cursor, so this fails:

```javascript
db.empFile.findOne().skip(1).limit(1);
```

```
TypeError: db.empFile.findOne().skip is not a function
```

## 2.7 `distinct()` — unique values of a field

```javascript
db.empFile.distinct("Salary").sort().reverse();
```

```
[
  50000, 45000, 40000,
  35000, 30000, 28000,
  25000, 22000, 20000,
  18000, 15000
]
```

- `distinct()` returns a plain JS array, so ordinary array methods (`.sort()`, `.reverse()`) work directly on the result — no aggregation pipeline needed for something this simple.

Get the Nth-highest value from that array with a custom comparator and index:

```javascript
db.empFile.distinct("Salary").sort((a, b) => b - a)[2];
```

```
40000
```

- `.sort((a, b) => b - a)` sorts numerically descending (plain `.sort()` without a comparator sorts lexicographically, which breaks on numbers); `[2]` then indexes the 3rd element (0-based) — i.e. the 3rd-highest salary.

# Part 3 — Update Operations

## 3.1 `updateOne()` with `$set` — update a single field

**Why:** equivalent to a SQL `UPDATE ... SET ... WHERE ...`, but scoped to exactly one matching document.

SQL equivalent:

```sql
UPDATE employee SET Salary = 55000 WHERE emp_id = 1201;
```

General form:

```javascript
db.<collection>.updateOne({ <condition> }, { $set: { field: value } })
```

```javascript
db.empFile.updateOne({ emp_id: 1201 }, { $set: { Salary: 55000 } });
```

```
{
  acknowledged: true,
  insertedId: null,
  matchedCount: 1,
  modifiedCount: 1,
  upsertedCount: 0
}
```

- `matchedCount` = how many documents matched the filter; `modifiedCount` = how many were actually changed (can differ if the new value equals the old one).

## 3.2 `updateMany()` with `$inc` — apply a raise to every matching document

**Task:** give all SSE employees a 3000 hike.

Check the "before" state:

```javascript
db.empFile.find({ Designation: "SSE" }, { emp_id: 1, Salary: 1 });
```

```
[
  { _id: ObjectId('6a71af643e805a09e77a2887'), emp_id: 1203, Salary: 30000 },
  { _id: ObjectId('6a71af643e805a09e77a2888'), emp_id: 1204, Salary: 30000 }
]
```

Apply the increment to **all** matches:

```javascript
db.empFile.updateMany({ Designation: "SSE" }, { $inc: { Salary: 3000 } });
```

```
{
  acknowledged: true,
  insertedId: null,
  matchedCount: 2,
  modifiedCount: 2,
  upsertedCount: 0
}
```

- `$inc` adds the given amount to the existing field value (use a negative number to decrement) — unlike `$set`, it doesn't require knowing the current value up front.

Confirm the "after" state:

```javascript
db.empFile.find({ Designation: "SSE" }, { emp_id: 1, Salary: 1 });
```

```
[
  { _id: ObjectId('6a71af643e805a09e77a2887'), emp_id: 1203, Salary: 33000 },
  { _id: ObjectId('6a71af643e805a09e77a2888'), emp_id: 1204, Salary: 33000 }
]
```

## 3.3 `$set` to add a field that didn't previously exist

```javascript
db.empFile.updateOne({ emp_id: 1202 }, { $set: { Experience: 5 } });
```

- **Why:** `$set` doesn't require the field to already be present in the document — it creates it if missing, or overwrites it if present. This is how you retroactively add a new attribute to specific documents in a schema-less collection.

Confirm with pagination instead of a filter:

```javascript
db.empFile.find().skip(1).limit(1);
```

```
[
  {
    _id: ObjectId('6a71af643e805a09e77a2886'),
    emp_id: 1202,
    Name: 'manisha',
    Age: 40,
    Gender: 'Female',
    Salary: 50000,
    Designation: 'AM',
    Dept_id: 'D002',
    Experience: 5
  }
]
```

## 3.4 `$mul` — multiply a field's existing value

```javascript
db.empFile.updateOne({ emp_id: 1203 }, { $mul: { Salary: 1.1 } });
```

- **Why:** `$mul` applies a percentage-style change (here, a 10% raise) directly on the server, without reading the current value into application code first.

```javascript
db.empFile.find().skip(2).limit(1);
```

```
[
  {
    _id: ObjectId('6a71af643e805a09e77a2887'),
    emp_id: 1203,
    Name: 'khalil',
    Age: 27,
    Gender: 'Male',
    Salary: 36300,
    Designation: 'SSE',
    Dept_id: 'D001'
  }
]
```

## 3.5 `$rename` — rename a field across the collection

```javascript
db.empFile.updateMany({}, { $rename: { Name: "EmpName" } });
```

```
{
  acknowledged: true,
  insertedId: null,
  matchedCount: 18,
  modifiedCount: 18,
  upsertedCount: 0
}
```

- An empty filter `{}` matches **every** document, so this renames the field collection-wide in one call.

```javascript
db.empFile.find().skip(2).limit(1);
```

```
[
  {
    _id: ObjectId('6a71af643e805a09e77a2887'),
    emp_id: 1203,
    Age: 27,
    Gender: 'Male',
    Salary: 36300,
    Designation: 'SSE',
    Dept_id: 'D001',
    EmpName: 'khalil'
  }
]
```

## 3.6 `$unset` — remove a field

```javascript
db.empFile.find({ emp_id: 1202 });
```

```
[
  {
    _id: ObjectId('6a71af643e805a09e77a2886'),
    emp_id: 1202,
    Age: 40,
    Gender: 'Female',
    Salary: 50000,
    Designation: 'AM',
    Dept_id: 'D002',
    Experience: 5,
    EmpName: 'manisha'
  }
]
```

```javascript
db.empFile.updateOne({ emp_id: 1202 }, { $unset: { Experience: "" } });
```

```
{
  acknowledged: true,
  insertedId: null,
  matchedCount: 1,
  modifiedCount: 1,
  upsertedCount: 0
}
```

- The value paired with the field name in `$unset` (here `""`) is ignored by Mongo — only the **key** matters; convention is to use an empty string or `1`.

```javascript
db.empFile.find({ emp_id: 1202 });
```

```
[
  {
    _id: ObjectId('6a71af643e805a09e77a2886'),
    emp_id: 1202,
    Age: 40,
    Gender: 'Female',
    Salary: 50000,
    Designation: 'AM',
    Dept_id: 'D002',
    EmpName: 'manisha'
  }
]
```

## 3.7 `replaceOne()` — replace an entire document

```javascript
db.empFile.find({ emp_id: 1218 });
```

```
[
  {
    _id: ObjectId('6a71b6bbf56cd9c55b8de66e'),
    emp_id: 1218,
    Age: 24,
    Gender: 'Male',
    Salary: 28000,
    Designation: 'ASE',
    Dept_id: 'D003',
    EmpName: 'Emp18'
  }
]
```

```javascript
db.empFile.replaceOne(
  { emp_id: 1218 },
  { emp_id: 1218, EmpName: "Dhivya", Designation: "TL" },
);
```

```
{
  acknowledged: true,
  insertedId: null,
  matchedCount: 1,
  modifiedCount: 1,
  upsertedCount: 0
}
```

- **Why `replaceOne` is different from `updateOne`/`$set`:** `updateOne` with `$set` only touches the fields you name, leaving everything else intact. `replaceOne` swaps out the **entire document body** (aside from `_id`) for the new one you supply — every field not included in the replacement is gone.

```javascript
db.empFile.find({ emp_id: 1218 });
```

```
[
  {
    _id: ObjectId('6a71b6bbf56cd9c55b8de66e'),
    emp_id: 1218,
    EmpName: 'Dhivya',
    Designation: 'TL'
  }
]
```

- Note `Age`, `Gender`, `Salary`, and `Dept_id` are all gone — confirming the whole document was replaced, not merged.

# Part 4 — The Aggregation Pipeline

## 4.1 Pipeline shape and stage-to-SQL mapping

```javascript
db.<collection>.aggregate([ { stage1 }, { stage2 }, { stage3 } ])
```

- **Why:** the aggregation pipeline runs documents through a sequence of stages, each transforming the output of the one before it — conceptually similar to chaining SQL clauses, but as an explicit ordered list you control.

| Stage      | SQL equivalent                   |
| ---------- | -------------------------------- |
| `$match`   | `WHERE`                          |
| `$project` | `SELECT` (choose/reshape fields) |
| `$sort`    | `ORDER BY`                       |
| `$limit`   | `LIMIT`                          |
| `$skip`    | `OFFSET`                         |
| `$group`   | `GROUP BY`                       |
| `$lookup`  | `JOIN`                           |

Common accumulator/array operators used inside `$group`/`$project`: `$sum`, `$avg`, `$max`, `$min`, `$addToSet`, `$push`, `$first`, `$last`.

## 4.2 `$group` — count of employees in each department

```javascript
db.empFile.aggregate([{ $group: { _id: "$Dept_id", EmpCount: { $sum: 1 } } }]);
```

```
[
  { _id: 'D003', EmpCount: 5 },
  { _id: 'D001', EmpCount: 4 },
  { _id: 'D004', EmpCount: 3 },
  { _id: null, EmpCount: 1 },
  { _id: 'D002', EmpCount: 5 }
]
```

- `_id` in a `$group` stage is the **grouping key** (like the `GROUP BY` column); `$sum: 1` counts one per document, same idea as SQL's `COUNT(*)`.
- The `_id: null` bucket collects any documents where `Dept_id` doesn't match one of the named groups (e.g. `undefined`/missing on a document like the replaced `emp_id: 1218`).

## 4.3 `$group` with `$avg` — average salary by designation

```javascript
db.empFile.aggregate([
  { $group: { _id: "$Designation", AvgSalary: { $avg: "$Salary" } } },
]);
```

```
[
  { _id: 'SE', AvgSalary: 24000 },
  { _id: 'AM', AvgSalary: 52500 },
  { _id: 'ASE', AvgSalary: 20500 },
  { _id: 'Lead', AvgSalary: 37500 },
  { _id: 'SSE', AvgSalary: 34650 },
  { _id: 'TL', AvgSalary: null }
]
```

- The `TL` group averages to `null` because that document (emp_id 1218, after `replaceOne`) no longer has a `Salary` field at all.

## 4.4 `$match` — filtering inside the pipeline

Plain `find()` filter, for comparison:

```javascript
db.empFile.find({ Salary: { $gt: 30000 } });
```

Equivalent as a pipeline stage:

```javascript
db.empFile.aggregate([{ $match: { Salary: { $gt: 30000 } } }]);
```

- **Why use `$match` instead of `find()`:** on its own, no real advantage — but `$match` is what lets you filter **as one stage among several**, e.g. filter first, then group, then sort, all in a single pipeline call.

## 4.5 `$match` + `$group` — count by designation, within one department

```javascript
db.empFile.aggregate([
  { $match: { Dept_id: "D002" } },
  { $group: { _id: "$Designation", empCount: { $sum: 1 } } },
]);
```

```
[
  { _id: 'SSE', empCount: 1 },
  { _id: 'ASE', empCount: 3 },
  { _id: 'AM', empCount: 1 }
]
```

- **Why put `$match` first:** stages run in order, so filtering to `Dept_id: "D002"` before the `$group` means only that department's documents are grouped — same principle as filtering before aggregating in SQL for performance and correctness.

## 4.6 `$match` with multiple conditions (implicit AND)

```javascript
db.empFile.aggregate([{ $match: { Dept_id: "D002", Salary: { $gt: 25000 } } }]);
```

## 4.7 `$match` with `$or`

```javascript
db.empFile.aggregate([
  { $match: { $or: [{ Dept_id: "D002" }, { Salary: { $gt: 25000 } }] } },
]);
```

- Same `$or` semantics as a regular `find()` filter — the aggregation pipeline reuses ordinary MongoDB query syntax inside `$match`.

## 4.8 `$group` then `$match` — "having"-style filtering on an aggregate

**Task:** find the `Dept_id` with more than 3 employees.

```javascript
db.empFile.aggregate([
  { $group: { _id: "$Dept_id", Empcount: { $sum: 1 } } },
  { $match: { Empcount: { $gt: 3 } } },
]);
```

```
[
  { _id: 'D003', Empcount: 5 },
  { _id: 'D001', Empcount: 4 },
  { _id: 'D002', Empcount: 5 }
]
```

- **Why `$match` appears twice in this document with different roles:** placed _before_ `$group`, it filters raw documents (like SQL `WHERE`). Placed _after_ `$group`, it filters on the computed aggregate (like SQL `HAVING`) — same operator, different position, different meaning.

## 4.9 `$sort` + `$limit` — top-N by an aggregate-friendly field

**Task:** top 5 highest-paid employees.

```javascript
db.empFile.aggregate([{ $sort: { Salary: -1 } }, { $limit: 5 }]);
```

- Equivalent to `find().sort({Salary:-1}).limit(5)` — shown here as pipeline stages since later examples build on chaining several stages together, which plain `find()` chaining can't do (e.g. combining with `$group` first).

## 4.10 Second-highest salary overall — `$addToSet` + `$unwind` + `$sort` + `$skip` + `$limit`

**Why this combination:** `$group` with `$addToSet` collects all _distinct_ salaries into one array per group — but you can't `$sort`/`$skip` inside an array field directly. `$unwind` flattens that array back into one document per element, so the rest of the pipeline can sort and paginate over individual values again.

```javascript
db.empFile.aggregate([
  { $group: { _id: null, Salaries: { $addToSet: "$Salary" } } },
  { $unwind: "$Salaries" },
  { $sort: { Salaries: -1 } },
  { $skip: 1 },
  { $limit: 1 },
]);
```

```
[ { _id: null, Salaries: 50000 } ]
```

- Step by step: `$group` with `_id: null` collapses the whole collection into a single group holding a deduplicated array of every salary → `$unwind` turns that one array-document into many single-value documents → `$sort` ranks them highest first → `$skip: 1` drops the highest, leaving the 2nd-highest at the front → `$limit: 1` takes just that one.

## 4.11 Second-highest salary **within each department** — `$sortArray` + `$arrayElemAt`

**Why:** the previous approach (`$unwind` + `$skip` + `$limit`) only works for a single overall ranking. To get the 2nd-highest **per group** in one pass, sort the array in place with `$sortArray`, then pick a specific index with `$arrayElemAt` — no `$unwind` needed.

```javascript
db.empFile.aggregate([
  { $group: { _id: "$Dept_id", Salaries: { $addToSet: "$Salary" } } },
  {
    $project: {
      SecondHighestSalary: {
        $arrayElemAt: [{ $sortArray: { input: "$Salaries", sortBy: -1 } }, 1],
      },
    },
  },
]);
```

```
[
  { _id: 'D003', SecondHighestSalary: 22000 },
  { _id: 'D001', SecondHighestSalary: 36300 },
  { _id: 'D004', SecondHighestSalary: 25000 },
  { _id: null },
  { _id: 'D002', SecondHighestSalary: 45000 }
]
```

- `$sortArray: { input: <array>, sortBy: -1 }` sorts the array field itself (descending here) without flattening it into separate documents.
- `$arrayElemAt: [<array>, 1]` then indexes into that sorted array — index `1` is the 2nd element (0-based), i.e. the second-highest value.
- The `_id: null` group has no `SecondHighestSalary` at all, since its `Salaries` array doesn't have a 2nd element to index.

## 4.12 `$push` — collect values into an array (duplicates kept)

```javascript
db.empFile.aggregate([
  { $group: { _id: "$Dept_id", Salaries: { $push: "$Salary" } } },
]);
```

```
[
  { _id: 'D003', Salaries: [ 40000, 22000, 18000, 18000, 18000 ] },
  { _id: 'D001', Salaries: [ 55000, 36300, 15000, 20000 ] },
  { _id: 'D004', Salaries: [ 35000, 25000, 25000 ] },
  { _id: null, Salaries: [] },
  { _id: 'D002', Salaries: [ 50000, 33000, 15000, 15000, 45000 ] }
]
```

- **`$push` vs `$addToSet`:** `$push` keeps every value, including duplicates (e.g. D003 shows `18000` three times); `$addToSet` dedupes. Choose based on whether repeated values matter to what you're building.

## 4.13 `$size` — count elements in an array field

```javascript
db.empFile.aggregate([
  { $group: { _id: "$Dept_id", Employees: { $push: "$EmpName" } } },
  { $project: { Employees: 1, count: { $size: "$Employees" } } },
]);
```

```
[
  { _id: 'D003', Employees: [ 'kiran', 'kranthi', 'Atul', 'lavanya', 'Emp16' ], count: 5 },
  { _id: 'D001', Employees: [ 'gopal', 'khalil', 'bhavya', 'Arshad' ], count: 4 },
  { _id: 'D004', Employees: [ 'laxmi', 'Satish', 'Krishna' ], count: 3 },
  { _id: null, Employees: [ 'Dhivya' ], count: 1 },
  { _id: 'D002', Employees: [ 'manisha', 'prasanth', 'reshma', 'Abhilasa', 'Emp17' ], count: 5 }
]
```

- **Why `$size` here instead of just `$sum: 1` from the earlier count example:** this counts elements of an **array already built by `$push`**, useful when you want the list _and_ its length together in the same output document, rather than a separate `$group` pass.

## 4.14 `$slice` — take a subset of an array field

```javascript
db.empFile.aggregate([
  { $group: { _id: "$Dept_id", Salaries: { $addToSet: "$Salary" } } },
  { $project: { Top2Salaries: { $slice: ["$Salaries", 2] } } },
]);
```

```
[
  { _id: 'D003', Top2Salaries: [ 18000, 22000 ] },
  { _id: 'D001', Top2Salaries: [ 55000, 36300 ] },
  { _id: 'D004', Top2Salaries: [ 35000, 25000 ] },
  { _id: null, Top2Salaries: [] },
  { _id: 'D002', Top2Salaries: [ 33000, 50000 ] }
]
```

- ⚠️ `$slice: [array, 2]` takes the **first 2 elements in whatever order the array is already in** — it does **not** sort first. That's why these aren't necessarily the two highest salaries (compare to §4.11, which explicitly sorts before picking an element).

## 4.15 `$first` / `$last` — first and last value seen per group

```javascript
db.empFile.aggregate([
  { $group: { _id: "$Dept_id", FirstEmployee: { $first: "$EmpName" } } },
]);
```

```
[
  { _id: 'D003', FirstEmployee: 'kiran' },
  { _id: 'D001', FirstEmployee: 'gopal' },
  { _id: 'D004', FirstEmployee: 'laxmi' },
  { _id: null, FirstEmployee: 'Dhivya' },
  { _id: 'D002', FirstEmployee: 'manisha' }
]
```

```javascript
db.empFile.aggregate([
  { $group: { _id: "$Dept_id", LastEmployee: { $last: "$EmpName" } } },
]);
```

```
[
  { _id: 'D003', LastEmployee: 'Emp16' },
  { _id: 'D001', LastEmployee: 'Arshad' },
  { _id: 'D004', LastEmployee: 'Krishna' },
  { _id: null, LastEmployee: 'Dhivya' },
  { _id: 'D002', LastEmployee: 'Emp17' }
]
```

- **Why these are order-dependent:** `$first`/`$last` return whichever document happened to be first/last **within the group as the pipeline saw it** — without a `$sort` stage before the `$group`, that order isn't guaranteed to mean anything in particular (e.g. "oldest hire" or "highest paid"). Add a `$sort` stage before `$group` if you need `$first`/`$last` to mean something specific.

## 4.16 `$pop` — remove the first or last element of an array field

```javascript
db.empFile.updateOne({ emp_id: 1217 }, { $pop: { Skills: -1 } });
```

```javascript
db.empFile.updateOne({ emp_id: 1217 }, { $pop: { Skills: 1 } });
```

- `$pop: { field: -1 }` removes the **first** element of the array; `$pop: { field: 1 }` removes the **last** element. (Other array-editing update operators worth knowing alongside this: `$filter`, `$in`, `$pull` — for conditionally removing elements by value rather than by position.)

## Quick recap — Day 2

| Concept                       | Key point                                                                                                                   |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `find()` vs `findOne()`       | `find()` returns a cursor/array of all matches; `findOne()` returns a single document (or `null`)                           |
| Projection                    | 2nd argument to `find`/`findOne`; `{field: 1}` = inclusion, `{field: 0}` = exclusion — can't mix the two (aside from `_id`) |
| `.sort({field: 1\|-1})`       | `1` ascending, `-1` descending                                                                                              |
| `.skip(n).limit(m)`           | Standard pagination pair; only valid on a cursor (`find()`), not on `findOne()`'s single result                             |
| `distinct(field)`             | Returns a plain JS array of unique values — ordinary array methods work on the result directly                              |
| `updateOne` / `updateMany`    | Scope of the update; both take `{filter}, {update}`                                                                         |
| `$set`                        | Sets (or creates) a field to an exact value                                                                                 |
| `$inc` / `$mul`               | Increment / multiply an existing numeric field in place, without reading it first                                           |
| `$rename`                     | Renames a field; `{}` as the filter applies it to every document                                                            |
| `$unset`                      | Removes a field; the paired value is ignored, only the key matters                                                          |
| `replaceOne`                  | Replaces the **entire** document body (except `_id`) — unlike `$set`, unlisted fields are dropped                           |
| Aggregation pipeline          | Ordered array of stages, each transforming the previous stage's output                                                      |
| `$match`                      | `WHERE`-like filtering; before `$group` filters raw docs, after `$group` filters aggregates (`HAVING`-like)                 |
| `$group`                      | `GROUP BY`; `_id` is the grouping key, `null` groups everything into one bucket                                             |
| `$push` vs `$addToSet`        | `$push` keeps duplicates; `$addToSet` deduplicates                                                                          |
| `$unwind`                     | Flattens an array field back into one document per element — needed before sorting/paginating array values individually     |
| `$sortArray` + `$arrayElemAt` | Sort an array field in place, then pick an element by index — gets "Nth highest per group" without `$unwind`                |
| `$slice`                      | Takes elements from an array **as currently ordered** — does not sort first                                                 |
| `$first` / `$last`            | First/last value seen per group in pipeline order — meaningless without a preceding `$sort`                                 |
| `$pop`                        | Removes first (`-1`) or last (`1`) element of an array field                                                                |
