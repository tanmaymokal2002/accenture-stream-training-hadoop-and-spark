## 1. Why Big Data Matters

- Uncovers opportunities via insights from massive data processing.
- Finds patterns in data generated by **Humans, Machines, or Sensors**.
- Combined with ML → enables **predictive modeling**.
- Used across: Government, Healthcare, Media & Entertainment, Insurance, Banking/Finance, IoT.
- 📌 Stat: **$103 billion** growing industry; **3 million jobs** in Big Data.

## 2. The "4 Vs" of Big Data (HIGH-YIELD — matching MCQs guaranteed)

| V            | Meaning                                                                 | Example                                                                         |
| ------------ | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **Volume**   | Size of data (**data at rest**) — hundreds of GBs to petabytes          | Mobile phone carriers; "5TB of data"                                            |
| **Velocity** | Speed at which data is generated (**data in motion**)                   | Social media, IoT devices, connected cars; "sensor sends data every 30 sec"     |
| **Variety**  | Data from multiple sources/formats (**many forms**)                     | Healthcare; "360° customer view using marketing+sales+service+clickstream data" |
| **Veracity** | Data in doubt — incorrect, inconsistent, or missing (**data in doubt**) | Fake social media profiles; unclear if reviews are genuine                      |

⚠️ MCQ trap — memorize the one-word tag for each:

- Volume = **at rest**
- Velocity = **in motion**
- Variety = **many forms**
- Veracity = **in doubt**

⚠️ MCQ trap: A problem qualifies as "Big Data" if it has **at least 2 of the 4 Vs** — not all 4, and not just 1.

## 3. Scaling: Vertical vs Horizontal

| Term                   | Definition                                                                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Cluster**            | A set of nodes connected in a network                                                                                                                          |
| **Node**               | A computer/server that is part of a network                                                                                                                    |
| **Commodity Hardware** | Cheap, widely available, easily interchangeable hardware — Big Data clusters run on this, so **built-in fault tolerance is essential** (components fail often) |

### Vertical Scaling ("Scale Up")

- Upgrade/replace hardware specs (CPU, RAM, storage, etc.) of a **single existing machine**.
- Result: **single node**, larger capacity.

| Advantages                     | Disadvantages                          |
| ------------------------------ | -------------------------------------- |
| Easy to manage/implement       | Limited scaling (upper hardware limit) |
| Lower software/licensing costs | Single point of failure                |
| Less admin effort              | Longer downtime during maintenance     |
| Lower cooling costs            | Hardware upgrades can be costly        |
| Easier security management     |                                        |

### Horizontal Scaling ("Scale Out")

- Add **more machines** to the existing pool; distributes load across them.
- Result: **multiple nodes** forming a cluster (uses distributed file systems, clustering, load balancing).
- Examples: **HDFS, HBase, Cassandra, MongoDB, DynamoDB**.

| Advantages                          | Disadvantages                                |
| ----------------------------------- | -------------------------------------------- |
| Near-infinite scale                 | Complex architecture                         |
| Better fault-tolerance/availability | Higher software/licensing/operating cost     |
| Lower downtime during maintenance   | Harder security management                   |
| Efficient use of smaller systems    | Higher cooling costs, more data center space |
| Cheaper long-term                   | Needs extra networking config                |

⚠️ MCQ trap: **Vertical = single node**; **Horizontal = multiple nodes (cluster)**. Big Data systems favor **horizontal scaling**.

## 6. HDFS (Hadoop Distributed File System)

- **HDFS** = Hadoop Distributed File System — the **storage layer**.
- History: Google File System paper (**2003**) → Yahoo released **Hadoop** (**2006**, open-sourced).
- Breaks data into **blocks** — each block = **128 MB**.
- Cluster (Hadoop Cluster) structure:
  - **Master Node** (aka **Name Node**)
  - **Data Nodes** (aka Chunk Servers / Slave Nodes)

⚠️ MCQ trap: HDFS block size = **128 MB** (memorize this number).

## 7. Ingestion Tools

| Tool      | Purpose                                                                                                                          |
| --------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Sqoop** | Import/export data between **relational DBs** and HDFS; command-line; coordinates via **MapReduce**                              |
| **Flume** | Ingest **log data** (non-relational); distributed, reliable, fault-tolerant, streaming data flow architecture                    |
| **Kafka** | Ingest **real-time streaming data**; high throughput, scalable, reliable; works atop persistent distributed storage (e.g., HDFS) |
| **NiFi**  | Directed graphs of data routing/transformation/system mediation logic (not covered in video)                                     |

⚠️ MCQ trap — match tool to data type:

- Relational DB ↔ HDFS → **Sqoop**
- Log/non-relational data → **Flume**
- Real-time streaming → **Kafka**

## 8. Processing Tools

| Tool          | Key Facts                                                                                                                                                                                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **MapReduce** | Framework for parallel processing of huge datasets across commodity clusters; splits input → **map tasks** → sorts/shuffles → **reduce tasks**; compute & storage nodes are usually the **same** (data locality → high bandwidth)                                        |
| **Pig**       | High-level language (**Pig Latin**) + infrastructure; compiles to MapReduce; good for "embarrassingly parallel" tasks; easy, optimizable, extensible                                                                                                                     |
| **Hive**      | **SQL-like** data warehouse tool; converts SQL queries → MapReduce code; works on data already in HDFS; has CLI + JDBC driver                                                                                                                                            |
| **Spark**     | Open-source distributed general-purpose cluster-computing framework; originated **UC Berkeley, 2009**; supports batch, streaming, SQL, ML; code in R/Python/Java/Scala; **"Next-gen MapReduce"**; **10–100x faster** than MapReduce; made MapReduce/Pig largely obsolete |

⚠️ MCQ traps:

- **Hive = SQL on Hadoop** (converts SQL → MapReduce).
- **Pig = Pig Latin scripting language**, compiles to MapReduce.
- **Spark origin: UC Berkeley, 2009**; **10-100x faster** than MapReduce — testable numbers.

## 9. YARN & HBase

### YARN (Yet Another Resource Negotiator)

- Manages **resources across the whole Hadoop cluster** — the "**Cluster Operating System**".
- Pig, Hive, Spark, MapReduce, HBase all run **on top of** YARN.
- Introduced in **Hadoop 2.0** (before that, its function was embedded in MapReduce = Hadoop 1.0).

### HBase

- Open-source, **non-relational**, distributed database.
- Modeled after **Google's Bigtable**; written in Java.
- Runs **on top of HDFS**; provides Bigtable-like capabilities.
- Offers **low-latency (millisecond) query access**.

⚠️ MCQ trap: **YARN introduced in Hadoop 2.0** — before that, resource management was baked into MapReduce (Hadoop 1.0).

## 10. Security & Governance Tools

| Tool              | Purpose                                                                                                                                                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Apache Ranger** | **Centralized security administration**; fine-grained authorization (RBAC + attribute-based); central UI/REST APIs; centralized auditing                                                                                 |
| **Apache Knox**   | **Gateway** for REST APIs/UIs of Hadoop; single access point; provides proxying, authentication, client SDK/DSL services                                                                                                 |
| **Apache Atlas**  | **Governance** tool — metadata management, classification (e.g., PII, SENSITIVE tags), data lineage tracking, search/discovery, security & data masking (integrates with Ranger for classification-based access control) |

⚠️ MCQ trap — don't confuse:

- **Ranger** = security **administration/authorization**
- **Knox** = **gateway/proxy** for API access
- **Atlas** = **governance/metadata/lineage/classification**
